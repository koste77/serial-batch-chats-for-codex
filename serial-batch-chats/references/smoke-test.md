# 两聊天顺序检测

在当前项目下建立独立运行目录，避免触碰现有业务批次。使用本 skill 的计划、独立聊天创建、文件交接、主会话监控和验收门禁。真实测试会创建两个用户可见聊天，须有用户授权；不使用 subagent 冒充这两个聊天。

可用以下命令生成计划和提示，再按 desktop-fallback.md 校验和执行 run.json。生成器不创建聊天、不写答案或 PASS；运行目录必须是新目录。无双评审要求时省略最后两个角色。

```powershell
python -X utf8 '<skill>/scripts/prepare_smoke.py' --root '<项目根>' --run-dir '.batch-runs/smoke-01' --review-roles content repro
```

1. B01 题目：计算 `2 + 3`，保存输入、答案及独立验证。建立包含结果文件 SHA-256 的交接。
2. B02 题目：读取 B01 的结果和交接，核对实际文件摘要，再把该结果乘以 `4`。保存读取来源、摘要、答案和独立验证。

预期分别为 `5`、`20`，但只写在计划与测试判定中；评估执行聊天时不要先替它写答案或 PASS。

观察以下行为：

- 两个不同的真实 thread ID，完整标题、相同 projectId 和 cwd，持久化且出现在项目查询结果中；Windows 备用通道还须有项目刷新及侧栏标题控件回读成功的证据。
- B02 创建时间严格晚于 B01 正常完成、文件验收通过的时间。
- B02 的输入摘要与 B01 实际输出一致，计算正确；前批交接有真实用途。
- 所需评审记录、证据、交接和最终 transcript 均存在。若项目要求双 reviewer，两个批次各按项目规则执行；没有这类规则则无需为算术额外设审。
- 再次执行 --run 不增加聊天或重发输入；本地测试覆盖前批失败不放行、摘要篡改不放行、创建回执不明不重复创建。

汇总报告需区分“静态校验通过”“离线门禁测试通过”“真实两聊天通过”。任一真实批次失败时保留现场并报告，不用模拟记录补齐。

每批按创建排队、桌面启动既有消息、--run --watch、主会话审查写 primary_gate.json、再次 --run 放行的顺序执行。模型设置也核对创建回执与桌面控件。无真实测试授权时只跑离线测试，不额外创建聊天。
